What you actually get

A browser tab can't do this. A native app does it in one file.

PokéBonk Deck loads the real game from pokebonk.com — same servers, same accounts, same cloud saves — but the shell around it behaves like console software.

Controller

Real gamepad support

Chromium's Gamepad API is exposed to the game exactly as a browser would, so the game's own Xbox/PlayStation glyphs, remapping, stick-learning wizard and rumble all work. No touch-overlay remapping required.

Auto-update

The game updates itself

The client polls version.json out-of-process and reloads the game when the upstream build changes. Charcher ships often — you don't reinstall anything.

Saves

Progress that survives

The shell keeps a persistent Chromium profile, so the origin-scoped localStorage that holds your session, guest identity and device id is still there tomorrow.

Display

Fullscreen, no distractions

Kiosk-mode window on launch at the Deck's native resolution. No address bar, no tab strip, no scrollbars — just the game.

Distribution

One AppImage

Download, mark executable, add to Steam as a non-Steam shortcut. The app also self-updates through the same AppImage channel when the shell itself ships a fix.

Footprint

Nothing bundled, nothing tracked

No game assets, no art, no music and no saves are redistributed — the client only loads the official site. No telemetry, no ad SDK, no account required.

The honest version

It's a wrapper — deliberately.

The game ships as a web app. The upstream developer states it is only distributed as a website, so this project does not repackage the game, mirror its assets, or ship an offline copy. It runs the live site.

  • 01Loads https://pokebonk.com/ as a top-level document — the site's CSP forbids iframe embedding, so a framed build is not an option.
  • 02Detects the upstream build id from version.json and reloads when it changes.
  • 03Keeps one persistent profile per user so your session survives restarts.
  • 04Adds the console-shaped parts the browser can't: kiosk fullscreen, a clean exit path, and an update channel.

Install

Three steps on the Deck.

The AppImage is self-contained — SteamOS already ships every library it needs, so there is nothing to install and no root required.

Download the AppImage

Grab PokebonkDeck-1.0.0-x86_64.AppImage from the project's releases page and copy it to the Deck (microSD, USB, or straight from a browser).

Make it executable

In the Deck's desktop mode terminal, or from any SSH shell on your network:

chmod +x ~/Downloads/PokebonkDeck-1.0.0-x86_64.AppImage
# optional: install it somewhere stable
mv ~/Downloads/PokebonkDeck-*.AppImage ~/.local/share/pokebonk-deck/

Add it to Steam and play

Library → Add a Non-Steam Game → browse to the AppImage. Set the launch option to gamemoderun %command% so the Deck's performance governor and gamescope session kick in.

# Steam shortcut launch option
gamemoderun %command%

Let it update itself

The client checks the upstream build on launch and reloads when it changes. The shell itself also self-updates through the AppImage channel — no re-downloading, no reinstalling.

# what the client checks, out-of-process
GET https://pokebonk.com/version.json
# {"build":"mvpt1dlr","version":"0.8.59"}

Tips & tricks

Play it better on the Deck.

Some of this is controller-specific, some is just good survivor-game discipline. All of it is verified against the current live build.

01

Bind the right stick early

The game has a stick-direction learning wizard that stores your camera mapping per controller. Do it once, on the first run, and the camera stays where you want it forever.

02

Pick the passive, not the sprite

Bulbasaur heals on Grass hits, Charmander gets a damage spike below 40% HP, Squirtle trades damage for armour and shield. The passive is what carries a run.

03

Hold the ultimate for the boss

Every Pokémon has its own ultimate type — Bulbasaur's Furious Roots and Frenzy Plant are crowd-clearers. Auto-ultimate exists, but a saved ultimate is usually worth more.

04

Learn the draft shortcuts

F rerolls, X skips, Z banishes an upgrade. On a controller these are one button each, so you can rebuild a build mid-wave instead of mousing through the menu.

05

Turn on auto-run when you farm

T toggles auto-run. Pair it with M for the big map to plan the next route instead of wandering.

06

Deck hygiene

Keep the AppImage on internal storage, not a FAT32 SD card — the self-updater replaces the file in place and a rename across filesystems fails. Use gamemoderun %command% as the Steam launch option.

FAQ

Questions people actually ask.

Does this work offline?

No. PokéBonk has no service worker and its accounts, rankings and seasons live on api.pokebonk.com, so the game needs the network. This client does not mirror or bundle the game — it plays the live site, which is also why updates arrive without reinstalling.

Will it work with my account?

Yes. The client loads the real pokebonk.com origin, so you sign in exactly as you would in a browser and your cloud saves stay in sync. The guest session and device id live in the client's persistent profile, so they survive restarts.

My controller doesn't work in the game.

Chromium only reports a gamepad after the user has interacted with one, so press a button on the Deck's controls once the game is up. If the pad still doesn't appear, check that Steam Input is set to a Gamepad layout rather than Desktop, and that you're running the native Linux build — a Proton/Windows build is a different code path.

How do updates work?

Two separate channels. The game updates on its own: the client fetches version.json from the main process and reloads the game when the build id changes. The client updates through the AppImage channel — the running app checks for a newer release and replaces itself on next launch.

Is this legal / allowed?

It is an unofficial client that plays the publicly available website, ships no game assets, and links out to the creator's Discord. It is not affiliated with or endorsed by the game's creator or by Nintendo. Keep using the official site directly if you prefer — this project exists because a browser tab is a poor fit for a Deck.

Which platforms are supported?

Linux x86-64 is the supported target, which covers Steam Deck (SteamOS 3) and any desktop Linux. The AppImage is self-contained; SteamOS already ships every library it needs, and the Electron sandbox works through unprivileged user namespaces, so no --no-sandbox and no root are required.
